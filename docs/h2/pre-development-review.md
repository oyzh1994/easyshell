# H2 功能开发前文档审核

- 审核日期：2026-11-28
- 审核对象：`docs/h2/requirements-and-design.md`
- 参照实现：`docs/sqlite/requirements-and-design.md`、`docs/sqlite/implementation-and-test-report.md` 及 `cn.oyzh.easyshell.sqlite` 全量代码
- 审核结论：修改后批准进入开发

## 1. 完整性检查

- 已覆盖用户、范围、流程、H2 能力边界、UI、数据结构、模块、接口、异常、兼容性、测试与验收。
- 已明确三种连接模式（文件/内存/远程）的字段映射与 URL 构造规则。
- 已明确单 schema 管理边界与函数设计器不做的原因（H2 持久化函数为 Java 别名，无法 SQL 表达式化），与 SQLite"不伪造能力"的先例一致。
- 已覆盖文件创建/打开/只读/丢失/损坏、内存库生命周期、远程连接失败场景。

## 2. 架构一致性

- 继续使用 `ShellConnect`、`ShellBaseClient`、`DBClient`、`DBConnManager`、`DBQueryResult`、`RichTab`、`RichTreeView`、`TerminalPane` 和 FXML/国际化机制。
- 底层 `SqlDatabase.H2` 已存在于 base-common（`cn.oyzh.common.db.SqlDatabase`），`fx-db` 只需在 `DBDialect` 枚举新增 `H2` 并在 `DBBaseSqlParser` 构造器 switch、`DBUtil.wrap/isSqlDialect/unwrapData`、`DBDataUtil.escapeQuotes` 中补齐 H2 分支。
- H2 客户端采用与 SQLite 相同的 `implements ShellBaseClient, DBClient` 双接口模式。
- 新增/修改连接控制器与 SQLite 保持相同结构，分别直接继承 `StageController`，保存使用 `insert`/`replace`。
- 数据处理复用 `fx-db` 的 `DBData*Handler` 体系；dump/transport/run-file 处理器需传 `DBDialect.H2`。

## 4. 发现的问题与修正

| 问题 | 风险 | 修正 |
| --- | --- | --- |
| H2 标识符未加引号时统一转大写，用户输入 `myTable` 会查不到 | 元数据查询失配 | SQL 生成统一双引号引号化；`INFORMATION_SCHEMA` 查询用大写；对象名匹配采用大小写不敏感策略 |
| H2 DDL 自动提交，多语句批次事务回滚对 DDL 无效 | 用户误以为可回滚 | 文档明确 DDL 自动提交语义；执行结果逐条记录状态；错误信息单独提示 |
| 内存库 `DB_CLOSE_DELAY` 未设置时最后连接关闭即销毁 | 数据意外丢失 | 默认内存连接追加 `DB_CLOSE_DELAY=-1`；连接信息提示销毁行为 |
| "文件不存在时创建"若默认开启，路径拼写错误会静默创建空库 | 数据混淆 | 默认关闭 `createIfMissing`；未开启且文件不存在时连接直接报错（复用 SQLite `IFEXISTS` 语义：H2 通过先检查文件存在再决定 URL 属性实现） |
| 文件路径带 `.mv.db` 后缀时 H2 会生成 `xxx.mv.db.mv.db` | 文件混乱 | 路径规范化时剥离 `.mv.db` 后缀后再拼 URL |
| 远程模式复用 `host/port/database` 字段而文件模式 `host` 存路径，两种模式语义不同 | 配置混乱 | `environment` 增加 `urlMode=file|mem|tcp` 显式声明，默认 `file`；连接配置读取时按 `urlMode` 分派字段语义 |
| 照搬 SQLite 表重建逻辑到 H2 属多余且危险（H2 支持标准 ALTER） | 数据丢失风险 | 表更新使用 ALTER 序列；仅列删除等不可 ALTER 的场景提示需重建（H2 2.x 支持 DROP COLUMN，正常无需重建） |
| `EXPLAIN QUERY PLAN` 是 SQLite 语法，H2 不支持 | 查询页 Explain 失败 | H2 使用 `EXPLAIN PLAN FOR <sql>`（返回文本计划） |
| H2 2.x `INFORMATION_SCHEMA.COLUMNS` 无 `COLUMN_DEFAULT` 同名旧列等布局差异 | 元数据查询失败 | 以 H2 2.x 官方 INFORMATION_SCHEMA 布局为准编写查询，集成测试真连 H2 验证 |
| 终端 `use` 在 H2 中语义应为切 schema 而非切库 | 命令行为混淆 | `use <schema>` 执行 `SET SCHEMA <schema>`；`show schemas;` 列出 schema |
| SQLite 树含 function 分组与函数设计器，H2 无对应能力 | 功能误导 | H2 树不设 function 分组，不提供函数设计器；`isSupportFeature` 相应收窄 |
| fx-db 为独立安装的本地模块（1.3.8），改动后需先 install | 构建顺序 | 开发顺序：先 `mvn -pl fx-db install`，再改 EasyShell |
| FXML 资源与包结构可能漏集成 | 运行时加载失败 | 新增 `ShellH2ArchitectureTest`：FXML 清单、类型路由、控制器注解、i18n 完整性、树结构对齐 SQLite |
| H2SVGGlyph 是否存在于 fx-plus 未最终确认 | 图标缺失编译失败 | 开发第一步验证；若不存在则自建 `H2SVGGlyph`（参照 SqliteSVGGlyph） |

## 5. 测试可执行性

- 通用方言与 URL 构造测试不依赖 JavaFX，可在 Maven 单元测试中直接执行。
- 集成测试使用 JUnit 临时目录的真实文件库（对齐 SQLite 测试模式），部分用例可使用 `jdbc:h2:mem:` 内存库加速；不依赖外部服务。
- UI 架构测试检查类型分派和资源存在性，JavaFX 平台通过 `Platform.startup` 启动（对齐 SQLite 架构测试模式）。
- 集成测试覆盖事务、元数据、只读、设计器 DDL、数据格式、dump、SQL 文件、传输和边界条件，测试结束关闭临时数据库客户端并清理临时目录。

## 6. 与 SQLite、MySQL/达梦实现的差异

- 连接模式：SQLite 仅本地文件；H2 增加内存与远程 TCP 模式，连接表单多出模式单选与对应字段。
- Schema：SQLite 无 schema（固定 `main`）；H2 有标准 schema，本期管理单一默认 schema，元数据查询带 schema 条件。
- 元数据来源：SQLite 用 `sqlite_master` + `PRAGMA`；H2 用 `INFORMATION_SCHEMA` 标准表。
- 函数：SQLite 提供能力适配的函数设计器（表达式/表函数视图/生成列）；H2 持久化函数为 Java 别名，本期不提供函数设计器。
- 表更新：SQLite 用事务内临时表重建；H2 用标准 `ALTER TABLE` 序列。
- 自增：SQLite `INTEGER PRIMARY KEY` + `AUTOINCREMENT`；H2 用 `IDENTITY`/`GENERATED BY DEFAULT AS IDENTITY`，且不提供重置自增动作。
- Explain：SQLite `EXPLAIN QUERY PLAN`；H2 `EXPLAIN PLAN FOR`。
- 驱动：sqlite-jdbc 带原生库（需 `SQLiteNativeCache` 预解压）；H2 纯 Java，无原生库处理。
