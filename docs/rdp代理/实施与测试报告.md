# EasyShell RDP 代理实施与测试报告

> 测试日期：2026-10-23
> 目标 RDP：`192.168.22.157:3389`（凭据仅用于本次测试，未写入本报告）

## 1. 实施结果

### 1.1 RDP 代理链路

- 新增 `RDPProxyTunnel`，在 `127.0.0.1` 暴露临时 TCP 端口，将内建 RDP 客户端和系统 RDP 客户端的连接转发至代理。
- `ShellProxyUtil.createSocket()` 补齐 HTTP CONNECT，并保留 SOCKS5 握手；支持 HTTP Basic、SOCKS5 用户名密码以及无需认证。
- `ShellRDPClient` 在启用代理时创建/关闭中继，并把 `RdpClient.connect()` 与 `.rdp` 文件地址切换到本地中继端口。
- `ShellConnectUtil` 的 RDP 连接测试改为执行 X.224 RDP 连接协商，不再直接探测目标端口。
- `ShellRDPUtil.initRDPFile()` 增加可指定连接地址/端口的重载，系统 RDP 客户端同样经过代理中继。

### 1.2 RDP UI

新增和修改 RDP 页面均增加“代理”标签页：

- 启用代理开关；
- 协议：HTTP、SOCKS；
- 代理地址和端口；
- 认证方式：无、密码；
- 认证用户名和密码。

启用开关和认证方式会联动禁用字段；保存、修改、连接测试都会校验必填项并持久化 `ShellConnect.proxyConfig`。代理密码只保存在连接配置中，不写入日志或文档。

## 2. Docker 代理服务

通用代理配置保留在 `docker/ssh/proxy/`：

| 服务 | 端口 | 协议 | 认证 |
|---|---:|---|---|
| `http-open` | `31280` | HTTP CONNECT | 无 |
| `http-auth` | `31281` | HTTP CONNECT | Basic `proxyuser` / `proxy-pass` |
| `socks-open` | `31282` | SOCKS5 | 无 |
| `socks-auth` | `31283` | SOCKS5 | 用户名密码 `proxyuser` / `proxy-pass` |

Docker 文件包括 `Dockerfile`、`entrypoint.sh`、`docker-compose.yml`、`test_tcp_proxy.py`、`run-tests.sh` 和 `README.md`。配置与测试工具均为协议无关；测试完成后四个容器保持运行，便于其他协议人工复测。

## 3. 测试执行

### 3.1 单元和本地协议测试

命令：

```bash
mvn -q -Dtest=RDPProxyTunnelTest test
```

结果：8 个测试全部通过。

覆盖：

- HTTP CONNECT 免认证；
- HTTP CONNECT Basic 认证；
- HTTP 认证缺失/错误凭据拒绝；
- SOCKS5 免认证；
- SOCKS5 用户名密码认证；
- SOCKS5 认证缺失/错误凭据拒绝；
- 本地 RDP 代理中继双向转发；
- 直连 RDP X.224 握手。

### 3.2 Docker 集成测试

命令：

```bash
cd docker/ssh/proxy
TARGET_HOST=192.168.22.157 TARGET_PORT=3389 BENCHMARK=1 \
  PROBE_SEND_HEX=030000130ee000000000000100080003000000 \
  PROBE_READ_BYTES=5 PROBE_EXPECT_PREFIX_HEX=030000130e \
  ./run-tests.sh
```

结果：协议无关代理工具使用运行参数注入本次 RDP 探针，四个代理场景全部通过：

```text
[PASS] http-open: HTTP/1.1 200 Connection established
[PASS] http-auth: HTTP/1.1 200 Connection established
[PASS] socks-open: SOCKS5 CONNECT succeeded
[PASS] socks-auth: SOCKS5 CONNECT succeeded
```

完整的 RDP X.224 Connection Request/Connection Confirm 由 Java 集成测试执行，RDP 协议常量不进入通用 Docker 目录。

Java 集成测试命令：

```bash
mvn -q -Drdp.proxy.it=true -Dtest=RDPProxyTunnelTest,RDPProxyDockerIntegrationTest test
```

结果：通过；认证服务的错误凭据测试也通过。
