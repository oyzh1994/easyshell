# EasyShell RDP 代理实现方案

> 编写日期：2026-10-23
> 状态：开发前设计基线；开发与测试完成后由《实施与测试报告》记录实际结果。

## 1. 目标与范围

- 为 EasyShell 的 RDP 连接增加 HTTP CONNECT 与 SOCKS5 代理能力。
- 支持无需认证与用户名/密码认证两种代理认证方式。
- 代理配置与 Redis、SSH 连接页面保持一致，并可持久化、编辑和用于连接测试。
- 内建 RDP 客户端和系统 RDP 客户端都通过同一代理链路连接目标主机。
- 提供可人工复测的 Docker 代理服务配置，并覆盖功能测试和连接建立基准测试。
- 使用真实 RDP 主机 `192.168.22.157:3389` 验证协议链路；测试文档不保留明文目标密码。

## 2. 现状结论

| 模块 | 当前行为 | 对 RDP 的启示 |
|---|---|---|
| Redis/ZK | 由客户端 SDK 自己应用 `ShellProxyConfig` | UI、配置模型可复用 |
| VNC | `ShellProxyUtil.createSocket()` 先连接代理，再执行 SOCKS5 握手 | 原始 TCP 握手方案可复用，但 HTTP CONNECT 缺失 |
| SSH | SDK 的 `ProxyHTTP`/`ProxySOCKS5` 支持认证 | HTTP Basic、SOCKS5 用户名密码认证语义对齐 |
| RDP | `fx-rdp` 仅暴露 `connect(host, port, ...)`，不接受自定义 Socket | 采用进程内本地 TCP 中继作为兼容层 |
| RDP UI | 当前仅有基础、扩展两个标签页 | 增加与 Redis 一致的“代理”标签页 |

## 3. 总体设计

### 3.1 连接链路

```text
fx-rdp / 系统 RDP
        |
        | TCP 127.0.0.1:<临时端口>
        v
RDPProxyTunnel（本地单连接中继）
        |
        | HTTP CONNECT 或 SOCKS5 握手
        v
Docker 代理服务
        |
        | TCP
        v
RDP 主机 192.168.22.157:3389
```

`ShellRDPClient` 在启用代理时启动本地中继，再让 `RdpClient.connect()` 连接中继地址。中继完成代理认证和目标连接后双向转发字节流。系统 RDP 客户端使用同一中继生成的 `.rdp` 文件地址，因此不依赖 `mstsc`/macOS RDP 客户端是否原生支持代理。

### 3.2 协议与认证

| 代理协议 | 请求方式 | 认证方式 | 说明 |
|---|---|---|---|
| HTTP | `CONNECT host:port HTTP/1.1` | 无 / Basic | 仅接受 `2xx` 响应；支持 IPv6 目标 |
| SOCKS5 | RFC 1928 CONNECT | 无 / RFC 1929 用户名密码 | 历史 `socks` 配置统一按 SOCKS5 处理 |

认证失败、代理拒绝、连接超时、协议格式错误均关闭中继并向上层抛出明确异常。代理密码不会写入日志和文档。

### 3.3 生命周期

- 每个 RDP 客户端实例最多维护一个活动代理中继。
- 连接前启动中继并获取本地端口，连接失败或 `close()` 时关闭中继。
- 中继只绑定 `127.0.0.1`，避免把本地端口暴露到局域网。
- 使用守护线程进行接收和双向复制；关闭时唤醒等待并释放 Socket/ServerSocket。

## 4. UI 与持久化

- 新增/修改 RDP 页面均增加代理标签页。
- 控件包括启用开关、协议、地址、端口、认证方式、用户名、密码。
- 代理关闭时禁用代理字段；认证方式为“无”时隐藏/禁用认证字段。
- 保存与连接测试均写入 `ShellConnect.enableProxy` 和 `ShellConnect.proxyConfig`。
- 校验启用代理时必填代理地址、端口；密码认证时必填用户名和密码。

## 5. Docker 测试服务

通用代理测试资产放在 `docker/ssh/proxy/`，长期保留：

- `docker-compose.yml`：启动 HTTP/SOCKS5 的认证与免认证四套服务。
- HTTP：Tinyproxy，支持 CONNECT 和 Basic 认证。
- SOCKS5：Dante，支持无认证与用户名/密码认证。
- `run-tests.sh`：启动服务、执行测试、输出结果并保留容器供人工复测。
- `README.md`：端口、账号、启动、复测和清理命令。

建议端口：

| 服务 | 容器端口 | 宿主端口 | 认证 |
|---|---:|---:|---|
| HTTP 免认证 | 3128 | 31280 | 无 |
| HTTP Basic | 3128 | 31281 | `proxyuser` / `proxy-pass` |
| SOCKS5 免认证 | 1080 | 31282 | 无 |
| SOCKS5 用户名密码 | 1080 | 31283 | `proxyuser` / `proxy-pass` |

## 6. 测试计划

### 6.1 单元与协议测试

- HTTP CONNECT：免认证成功、Basic 成功、错误凭据拒绝。
- SOCKS5：免认证成功、用户名密码成功、错误凭据拒绝。
- IPv4/域名目标、非法响应、目标拒绝、超时与关闭清理。

### 6.2 Docker 集成测试

- 四套代理服务均从宿主实际连接真实 RDP 3389 端口。
- 验证代理后的 TCP 数据可完成 RDP X.224 连接请求/响应握手。
- 验证无认证服务拒绝携带认证、认证服务拒绝无认证/错误认证的行为与所选服务配置一致。
- 保存 `docker compose ps`、测试输出和基准结果到报告。

### 6.3 RDP 基准测试

- 目标：`192.168.22.157:3389`。
- 场景：直连、HTTP 免认证、HTTP Basic、SOCKS5 免认证、SOCKS5 用户名密码。
- 预热 3 次，正式 20 次；统计最小值、平均值、P95、最大值。
- 基准口径为建立到真实 RDP 服务的 TCP 连接并读取 RDP X.224 响应，不包含 GUI 首帧。

## 7. 验收标准

- RDP 新增/修改界面可保存并恢复全部代理字段。
- 四种代理场景均能连接真实 RDP 主机，认证场景使用正确凭据成功、错误凭据失败。
- 内建 RDP 客户端经过中继连接，关闭后无监听端口和线程泄漏。
- Docker 配置文件和复测脚本保留且可重复启动。
- 单元测试、Docker 集成测试、真实 RDP 测试和基准结果均形成文档。
