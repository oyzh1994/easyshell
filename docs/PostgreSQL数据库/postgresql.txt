# PostgreSQL 数据库使用说明

本文说明如何在 EasyShell 中使用 PostgreSQL 协议，以及常用的数据库初始化、权限和对象创建 SQL。Docker 环境搭建见 `docker/postgresql/docker.txt`。

## 1. 连接

EasyShell 中选择“添加连接 -> 数据库 -> PostgreSQL”，填写：

```text
主机：127.0.0.1
端口：5432
数据库：postgres
用户：postgres
密码：<安装时设置的密码>
```

说明：

- PostgreSQL 一个 JDBC 连接对应一个数据库，因此 EasyShell 的连接配置中包含“数据库”字段；MySQL/达梦没有该字段。
- 连接成功后，树根显示当前数据库下的模式（Schema）。默认模式为 `public`，也可以连接后查看/新建其他模式。
- 切换数据库需要修改连接配置或新建连接；模式（Schema）可以在树中直接切换，终端中使用 `\c <模式名>` 切换 `search_path`。
- 勾选“启用 SSL”后，客户端以 `sslmode=require` 连接；服务端必须开启 SSL。
- 代理/跳板机、连接超时、环境参数与其他数据库一致；环境参数每行一个 `key=value`，详见 1.1。

### 1.1 连接参数（环境）

PostgreSQL 的“环境”文本域对应 pgjdbc 的连接属性，格式为每行一个 `key=value`。和 MySQL/达梦不同，PostgreSQL **没有必须预设的环境变量**，驱动默认值通常可以直接连接。EasyShell 新建 PostgreSQL 连接时默认预置：

```text
ApplicationName=EasyShell
tcpKeepAlive=true
reWriteBatchedInserts=true
```

常用参数：

| 参数 | 说明 | 示例 |
| --- | --- | --- |
| `ApplicationName` | 连接在 `pg_stat_activity` 中显示的名称 | `ApplicationName=EasyShell` |
| `currentSchema` | 设置默认 `search_path`，查询时未写模式名则使用该模式 | `currentSchema=demo` |
| `options` | 传递服务端参数，多个参数用空格分隔 | `options=-c statement_timeout=60000 -c lock_timeout=10000` |
| `connectTimeout` | 建立连接超时，单位秒 | `connectTimeout=10` |
| `loginTimeout` | 登录超时，单位秒 | `loginTimeout=10` |
| `socketTimeout` | 读写超时，单位秒；0 表示不限制 | `socketTimeout=60` |
| `tcpKeepAlive` | 开启 TCP keepalive | `tcpKeepAlive=true` |
| `reWriteBatchedInserts` | 将批量 INSERT 重写为多值 INSERT，提升导入性能 | `reWriteBatchedInserts=true` |
| `prepareThreshold` | 服务端预编译阈值，设为 0 可禁用预编译 | `prepareThreshold=5` |
| `binaryTransfer` | 启用二进制传输 | `binaryTransfer=true` |
| `sslmode` | SSL 模式：`disable`/`allow`/`prefer`/`require`/`verify-ca`/`verify-full` | `sslmode=require` |
| `sslrootcert` | CA 证书路径 | `sslrootcert=/path/ca.crt` |
| `sslcert` / `sslkey` | 客户端证书/私钥路径 | `sslcert=/path/client.crt` |
| `sslpassword` | 私钥密码 | `sslpassword=******` |
| `stringtype` | 字符串参数类型，`unspecified` 时交由服务端推断 | `stringtype=unspecified` |
| `targetServerType` | 多主机时的目标类型，如 `primary`/`prefer-standby` | `targetServerType=primary` |

示例：

```text
ApplicationName=EasyShell
currentSchema=demo
options=-c statement_timeout=60000 -c lock_timeout=10000
tcpKeepAlive=true
reWriteBatchedInserts=true
```

说明：

- 连接表单中的“连接超时”、SSL 复选框、代理配置已经分别处理 `connectTimeout/loginTimeout`、`sslmode=require`、`socketFactory/socketFactoryArg`，通常不需要在环境里重复填写。
- `currentSchema` 只影响当前连接；需要持久化默认模式可以使用 `ALTER ROLE oyzh SET search_path TO oyzh, public;` 或 `ALTER DATABASE testdb SET search_path TO ...;`。
- 需要持久化服务端参数（时区、语句超时等）可使用 `ALTER DATABASE ... SET ...` 或 `ALTER ROLE ... SET ...`；环境中的 `options` 只对当前连接生效。
- `stringtype=unspecified` 可以让枚举、jsonb、uuid 等类型的字符串参数由服务端推断，但 `SELECT ?` 这类无法推断类型的场景会报错；EasyShell 已对 JSON/JSONB、UUID、数组等参数自动加类型转换，通常不需要设置。
- 会话时区需要特别注意：pgjdbc 会根据 JVM 默认时区向服务端发送 `TimeZone` 启动参数，因此 `options=-c timezone=...` 可能被驱动覆盖。需要固定时区时，优先在启动 EasyShell 时设置 `-Duser.timezone=Asia/Shanghai`，或在连接后执行 `SET TIME ZONE 'Asia/Shanghai';`；服务端默认值可用 `ALTER DATABASE ... SET timezone = ...` 调整，但当前连接仍以驱动/JVM 时区为准。
- `currentSchema` 与 `options=-c search_path=...` 都可以设置默认模式；前者更简单，后者可以一次指定多个模式，例如 `options=-c search_path=demo,public`。

## 2. 创建测试数据库、用户和模式

使用管理员账号连接 `postgres` 数据库后执行：

```sql
-- 创建测试数据库
CREATE DATABASE testdb;

-- 创建测试用户
CREATE USER oyzh WITH PASSWORD '123456789';

-- 允许连接测试数据库
GRANT CONNECT ON DATABASE testdb TO oyzh;
```

然后切换到 `testdb` 数据库，创建用户自己的模式并授权：

```sql
-- 创建模式并指定所有者
CREATE SCHEMA IF NOT EXISTS oyzh AUTHORIZATION oyzh;

-- 模式使用与建对象权限
GRANT USAGE, CREATE ON SCHEMA oyzh TO oyzh;

-- 已有对象的访问权限
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA oyzh TO oyzh;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA oyzh TO oyzh;
GRANT EXECUTE ON ALL FUNCTIONS IN SCHEMA oyzh TO oyzh;

-- 以后新建对象的默认权限
ALTER DEFAULT PRIVILEGES IN SCHEMA oyzh
    GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO oyzh;
ALTER DEFAULT PRIVILEGES IN SCHEMA oyzh
    GRANT USAGE, SELECT ON SEQUENCES TO oyzh;
ALTER DEFAULT PRIVILEGES IN SCHEMA oyzh
    GRANT EXECUTE ON FUNCTIONS TO oyzh;
```

注意事项：

- PostgreSQL 15 起，普通用户默认不能在 `public` 模式建对象；建议为业务用户创建独立模式，或在目标数据库显式授权。
- 仅授予 `CONNECT` 还不够，访问对象还需要模式上的 `USAGE` 权限。
- 在 EasyShell 中如果看不到某个模式或者提示权限不足，优先检查 `CONNECT`、`USAGE`、表/序列/函数权限以及 `search_path`。

## 3. 常用对象示例

以下 SQL 与 EasyShell 的表、视图、函数、过程、序列、触发器功能一一对应。也可以直接使用 `docker/postgresql/init.sql` 初始化一套 `demo` 模式测试对象。

### 3.1 表

```sql
CREATE TABLE demo.users (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(64) NOT NULL,
    email TEXT UNIQUE,
    age INTEGER DEFAULT 18 CHECK (age >= 0),
    balance NUMERIC(12, 2) DEFAULT 0,
    active BOOLEAN DEFAULT TRUE,
    avatar BYTEA,
    profile JSONB,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

COMMENT ON TABLE demo.users IS '用户表';
COMMENT ON COLUMN demo.users.name IS '用户名';

CREATE INDEX idx_users_name ON demo.users (name);
```

外键补充说明：

- PostgreSQL 要求外键**被引用列**上存在唯一约束、主键或唯一索引，否则会报 `there is no unique constraint matching given keys for referenced table "xxx"`。这是数据库约束要求，不是 EasyShell 的生成错误。
- 复合外键的被引用列必须整体唯一，且列顺序一致。例如 `t1` 只有 `PRIMARY KEY (id)` 时，`FOREIGN KEY (t1_id, name) REFERENCES t1 (id, name)` 会失败，需要先执行：

```sql
ALTER TABLE demo.t1
    ADD CONSTRAINT uq_t1_id_name UNIQUE (id, name);
```

  或只引用真正唯一的列组合（上例中如果 `id` 已经唯一，通常只引用 `id` 即可）。
- 也可以在 EasyShell 表设计器的“索引”页为被引用表创建 `UNIQUE` 复合索引，再回到外键页保存。
- 外键的 `ON UPDATE` 与 `ON DELETE` 均支持 `CASCADE`、`RESTRICT`、`SET NULL`、`SET DEFAULT`、`NO ACTION`。

说明：

- EasyShell 表设计器支持 `GENERATED BY DEFAULT/ALWAYS AS IDENTITY`、默认值、NULL/NOT NULL、主键、唯一、检查、外键、索引和注释。
- 外键同时支持 `ON UPDATE` 与 `ON DELETE` 的 `CASCADE`、`RESTRICT`、`SET NULL`、`SET DEFAULT`、`NO ACTION`；PostgreSQL 不存在只能使用 `ON DELETE` 的限制。
- 表空间：PostgreSQL 中未显式指定表空间的表实际位于数据库默认表空间（通常是 `pg_default`）；EasyShell 会按实际生效的表空间回显，表设计器中显示 `pg_default` 属于正常现象。
- `SERIAL/BIGSERIAL` 也可使用；从已有 serial 表生成建表/转储 SQL 时会输出 `GENERATED ... AS IDENTITY`，避免依赖序列创建顺序。
- identity/serial 自动创建的序列不会显示在“序列”树中，避免误删。

### 3.2 视图

```sql
CREATE VIEW demo.v_users AS
SELECT id, name, email, age, active
FROM demo.users;

COMMENT ON VIEW demo.v_users IS '用户视图';
```

EasyShell 视图设计器使用 `CREATE OR REPLACE VIEW`，保留 `WITH [CASCADED|LOCAL] CHECK OPTION`；`SECURITY INVOKER` 会输出为 `WITH (security_invoker = true)`（需要 PostgreSQL 15+）。

### 3.3 序列

```sql
CREATE SEQUENCE demo.seq_order
    INCREMENT BY 1
    MINVALUE 1
    MAXVALUE 999999
    START WITH 1
    CACHE 1
    CYCLE;
```

修改序列使用 `ALTER SEQUENCE`；EasyShell 序列设计器支持递增值、最小值、最大值、当前值、缓存和循环。PostgreSQL 没有 `ORDER` 属性。

### 3.4 函数

```sql
CREATE OR REPLACE FUNCTION demo.fn_add(a INTEGER, b INTEGER)
    RETURNS INTEGER
    LANGUAGE plpgsql
AS $$
BEGIN
    RETURN a + b;
END;
$$;

COMMENT ON FUNCTION demo.fn_add(INTEGER, INTEGER) IS '加法函数';
```

EasyShell 函数设计器会生成 `CREATE OR REPLACE FUNCTION ... RETURNS ... LANGUAGE plpgsql AS $$...$$`，支持 `SECURITY DEFINER/INVOKER`、`IMMUTABLE/STABLE/VOLATILE`、`STRICT`、`PARALLEL SAFE`、`COST/ROWS` 等常用属性。

### 3.5 过程

```sql
CREATE OR REPLACE PROCEDURE demo.sp_noop()
    LANGUAGE plpgsql
AS $$
BEGIN
    NULL;
END;
$$;
```

PostgreSQL 11+ 支持存储过程；过程没有 `RETURNS`。EasyShell 修改过程时会先 `DROP PROCEDURE IF EXISTS` 再创建，以兼容不同版本。

### 3.6 触发器

PostgreSQL 触发器需要先创建返回 `trigger` 的函数，再创建触发器：

```sql
CREATE OR REPLACE FUNCTION demo.fn_users_normalize()
    RETURNS trigger
    LANGUAGE plpgsql
AS $$
BEGIN
    NEW.email := lower(NEW.email);
    RETURN NEW;
END;
$$;

CREATE TRIGGER trg_users_normalize
    BEFORE INSERT OR UPDATE
    ON demo.users
    FOR EACH ROW
EXECUTE FUNCTION demo.fn_users_normalize();
```

EasyShell 表设计器中的触发器会自动按 `<表名>_<触发器名>_fn` 生成配套函数；修改或删除触发器时会同步删除旧函数。

## 4. EasyShell 功能入口

连接打开后，左侧树结构为：

```text
模式
└── <schema>
    ├── 表
    ├── 视图
    ├── 函数
    ├── 过程
    ├── 序列
    ├── 查询
    └── 终端
```

- 表：打开表（分页数据）、设计表、重命名、清空、截断（`TRUNCATE ... RESTART IDENTITY`）、删除、转储、导出、克隆、表信息。
- 视图：打开视图数据、设计视图、重命名、删除、克隆、视图信息。
- 函数/过程：设计、重命名、删除、克隆、信息查看。
- 序列：设计、重命名、删除、克隆、信息查看。
- 查询：新建查询、保存、格式化、执行、Explain；`Ctrl/Cmd + R` 执行。
- 终端：支持 SQL 与 psql 风格元命令，见下一节。
- 底部工具栏：导入数据、导出数据、运行 SQL 文件、传输数据、定位节点。

## 5. 终端元命令

EasyShell 的 PostgreSQL 终端兼容常用 psql 元命令：

| 命令 | 说明 |
| --- | --- |
| `\l` | 列出所有数据库 |
| `\dn` | 列出当前数据库的模式 |
| `\dt` | 列出当前模式下的表 |
| `\d <表>` | 查看表结构 |
| `\df` | 列出函数 |
| `\dv` | 列出视图 |
| `\ds` | 列出序列 |
| `\dp` | 查看权限 |
| `\c <模式>` | 切换当前模式（`SET search_path TO "模式"`） |
| `\x` | 切换展开输出 |
| `\timing` | 切换执行耗时显示 |
| `\?` / `\h` | 帮助 |

对应的 SQL：

```sql
-- 数据库列表
SELECT datname FROM pg_database ORDER BY datname;

-- 模式列表
SELECT nspname
FROM pg_namespace
WHERE nspname NOT IN ('pg_catalog', 'information_schema')
  AND nspname NOT LIKE 'pg_toast%'
  AND nspname NOT LIKE 'pg_temp_%'
ORDER BY nspname;

-- 切换模式
SET search_path TO demo;

-- 表列表
SELECT relname
FROM pg_class c
JOIN pg_namespace n ON n.oid = c.relnamespace
WHERE n.nspname = 'demo' AND c.relkind IN ('r', 'p')
ORDER BY relname;
```

## 6. 数据类型与展示

EasyShell 已适配常用 PostgreSQL 类型：

- 字符：`CHAR/VARCHAR/TEXT/UUID/XML/INET/CIDR/MACADDR`
- 数值：`SMALLINT/INTEGER/BIGINT/NUMERIC/REAL/DOUBLE PRECISION/MONEY`
- 布尔：`BOOLEAN`
- 时间：`DATE/TIME/TIME WITH TIME ZONE/TIMESTAMP/TIMESTAMP WITH TIME ZONE/INTERVAL`
- 二进制：`BYTEA`（以十六进制展示）
- JSON：`JSON/JSONB`
- 位串：`BIT/BIT VARYING`
- 全文检索：`TSVECTOR/TSQUERY`
- 几何：`POINT/LINE/LSEG/BOX/PATH/POLYGON/CIRCLE`
- 自增：`SERIAL/BIGSERIAL/SMALLSERIAL/GENERATED ... AS IDENTITY`

JSON/JSONB、UUID、数组等类型在新增/修改记录时会自动加类型转换，避免 `column is of type jsonb but expression is of type character varying` 一类错误。

## 7. 注意事项

1. PostgreSQL 标识符默认折叠为小写；如果建对象时使用双引号包含大小写，后续也必须使用相同大小写访问。EasyShell 使用双引号包裹对象名，按目录中的实际名称展示。
2. PostgreSQL 没有 MySQL 的“事件/调度器”对象；如需定时任务可使用扩展 `pg_cron`，EasyShell 不提供事件树节点。
3. 一个连接只对应一个数据库；跨数据库查询需要使用 `dblink`/`postgres_fdw`，或在 EasyShell 中新建对应数据库的连接。
4. 视图默认不可通过简单规则保证更新；EasyShell 根据 `information_schema.views.is_updatable` 展示是否可编辑，复杂视图请直接在查询页执行 SQL。
5. 重载函数/过程在树中按名称展示；如果同名重载较多，设计/删除可能只针对第一个匹配项。需要精确管理时建议使用查询页执行带参数签名的 `DROP FUNCTION`/`ALTER FUNCTION`。
6. 分区表、表达式索引、索引 `INCLUDE`、`COLLATE`、`STORAGE/COMPRESSION` 等高级 DDL 目前支持有限；复杂的表结构修改建议直接执行 SQL。
7. 数据导入/导出/转储/传输使用 PostgreSQL 语法；跨模式传输会移除源模式名并写入目标模式，函数/过程/序列会按当前连接的模式重建。
8. 生产环境修改表结构前请先备份；EasyShell 的 DDL 预览可以在执行前确认实际 SQL。

## 8. 快速验证清单

1. 使用 Docker 启动 PostgreSQL，执行 `docker/postgresql/init.sql`。
2. 在 EasyShell 中新建 PostgreSQL 连接，数据库填 `postgres`，打开连接。
3. 展开 `demo` 模式，确认表、视图、函数、过程、序列数量正确。
4. 双击 `users` 表查看数据，确认 `JSONB/BYTEA/TIMESTAMP WITH TIME ZONE` 展示正常。
5. 新建查询执行 `SELECT * FROM demo.users;`，确认结果、耗时、结果集页签正常。
6. 在终端执行 `\dt`、`\dn`、`\c demo`、`\dt`，确认模式切换和表列表正常。
7. 新增一行记录，确认 identity 主键自动回显；修改/删除记录确认影响行数正确。
8. 右键表执行“设计表”“导出数据”“转储数据”“运行 SQL 文件”，确认对应窗口可打开并执行。

## 9. 关于 init.sql 的执行与事务

PostgreSQL 的 DDL 和 DML 都是事务性的，未提交的事务在连接关闭时会回滚。因此执行 `init.sql` 时推荐以下方式：

1. **Docker 初始化挂载（推荐）**：按 `docker/postgresql/docker.txt` 的“带测试对象启动”命令挂载 `init.sql`，由容器初始化流程自动提交。
2. **EasyShell 的“运行 SQL 文件”**：逐条执行并提交，适合已有数据库。
3. **EasyShell 查询页执行**：当前版本按 psql 的自动提交语义逐条执行，每条语句独立提交；某条失败不会影响后续语句（显式写 `BEGIN` 的事务中失败后需要执行 `ROLLBACK`）。旧版本查询页执行后不会提交，关闭连接会回滚，请更新客户端，或在脚本末尾补一行 `COMMIT;`。
4. **psql 命令行执行**：`psql -U postgres -d postgres -f /path/init.sql`，psql 默认自动提交。

如果关闭连接后 `demo` 模式消失，通常就是 `CREATE SCHEMA`/`CREATE TABLE` 等语句所在事务未提交被回滚，重新按上述任一方式执行即可。执行后建议关闭连接再重新打开确认对象仍然存在。
