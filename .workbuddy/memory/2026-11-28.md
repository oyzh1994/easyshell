## 索引设计推广到全部 SQL 数据库（共用实现）

- **用户要求**：在 Oracle 索引设计审核通过后推广到其他数据库；并提示 `ShellOracleIndexDesignTab#flushTitle` 的 i18n 资源已更新（现用 `I18nHelper.unnamedIndex()`）。
- **架构（关键收益，后续加库只做 4 个方法 + 1 个接口实现）**：
  - `cn.oyzh.easyshell.index.ShellIndex`：索引模型通用接口（name/tableName）；`ShellIndexTarget`：库/模式节点接口（dialect/connectName/indexScope/selectIndexes/selectIndexDefinition/executeIndexSql/existIndex/dropIndex/newIndex/reloadIndexes）。
  - `ShellIndexHelper`：`isCreateIndexSql`/`isDropIndexSql`/`parseIndexName`/`stripTerminator`（兼容 UNIQUE/BITMAP/CLUSTERED/NONCLUSTERED/FULLTEXT/SPATIAL、IF NOT EXISTS、`"``` ` ``[]` 包裹、schema 前缀）。
  - `index/event`：`ShellIndexDesignEvent`、`ShellIndexDroppedEvent`、`ShellIndexEventUtil`（全局事件，各面板按 `event.dialect()` 过滤，避免跨库误开 tab）。
  - `trees/index`：`ShellIndexesTreeItem(+Value)`、`ShellIndexTreeItem(+Value)`（`表名.索引名`、懒加载数量、增删改差异合并、参与搜索过滤）。
  - `tabs/index`：`ShellIndexDesignTab`、`ShellIndexDesignTabController`、`resources/tabs/index/shellIndexDesignTab.fxml`（单 SQL 编辑器，保存即执行；改索引自动先 DROP 再 CREATE）。
- **各库实现**（模型实现 `ShellIndex` 并补 tableName；客户端 4 方法；库/模式节点实现 `ShellIndexTarget` 并挂载索引类型节点；tabPane 两个事件处理 + `QueryUtil.refreshIndex`）：
  - MySQL/MariaDB：`information_schema.STATISTICS` 全库查询，定义由索引信息拼 `CREATE [UNIQUE|FULLTEXT|SPATIAL] INDEX ... USING ... COMMENT ...`，删除 `DROP INDEX x ON db.t`。
  - PostgreSQL：`pg_index` 全模式查询 + `PG_GET_INDEXDEF` 取定义，删除 `DROP INDEX s.i`。
  - SqlServer：`sys.indexes/index_columns` 查询，定义拼 `CREATE [UNIQUE] [CLUSTERED|NONCLUSTERED] INDEX ... INCLUDE(...) WHERE ...`，删除 `DROP INDEX i ON s.t`。
  - 达梦：`ALL_INDEXES/ALL_IND_COLUMNS` 全模式查询，定义优先 `DBMS_METADATA.GET_DDL`，失败按字典拼 `CREATE [UNIQUE|BITMAP] INDEX`，删除 `DROP INDEX s.i`。
  - SQLite：`sqlite_master` 全库查询（过滤 `sqlite_autoindex`），定义取 `sqlite_master.sql`，删除 `DROP INDEX i`，多语句用 `executeSqlSimple`。
- **Mongo 未纳入**：索引为集合级、无 SQL DDL（JSON/命令式），且集合设计页已有 `MongoIndexControl` 索引管理；如需可在集合节点加索引子节点，另做 JSON 定义页。
- **Oracle 保持原实现**（用户已调整其 i18n），仅让 `OracleIndex` 实现 `ShellIndex` 以便统一测试。
