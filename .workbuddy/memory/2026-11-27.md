  1. 导入字符集方向写反：`TextUtil.changeCharset(data, UTF-8, config.charset())`，读取器已按 config.charset() 解码，应为 config.charset() → UTF-8；且 `ShellZKClient.create/setData(String)` 用平台默认 `getBytes()`，非 UTF-8 文件往返会乱码。

  6. 三个控制器异常判断 `e.getClass().isAssignableFrom(InterruptedException.class)` 方向不严谨，应改 `e instanceof InterruptedException`。

### XML 导出含裸控制字符导致导入 ParseError（用户复测发现，已修）
- 现象：用户导出 db0 为 XML 后导入报 `XMLStreamException: 在文档的元素内容中找到无效的 XML 字符 (Unicode: 0x0)`。
- 根因：`ShellRedisKeyUtil.keyValue()` 用 `Jedis.get(String)` 以 UTF-8 解码二进制值（0xFF→U+FFFD 不可逆）；且 `isRawEncoding()` 只认 object encoding=="raw"，短二进制是 `embstr`，漏判，值走 `new String(bytes)` 把 0x00/0x01/0x02 裸写进 XML。`XMLUtil.escape()` 只处理 &<>\r，不处理 XML 1.0 禁止字符。
- 修复（3 处）：
  1. `keyValue()` string 分支改用 `client.get(db, key.getBytes(UTF8))` 读原始字节；新增 `isTextSafe()`（严格 UTF-8解码 + 检测 XML 禁止字符/代理项/0xFFFE），安全则按文本、否则保留 byte[]。
  2. `serializeNode()` string 分支按实际值类型判断（不再依赖 objectEncoding），byte[] 一律输出 `0x'hex'`（导入端 deserializeNode 已支持）。
  3. 导出 handler `escaped()` 增加最后防线：XML 格式剔除 0x00-0x1F 等禁止字符后再 XMLUtil.escape，保证文件必可解析。
- 回归测试：`ShellRedisDataLiveTest.binaryValueXmlExportIsParseableAndRoundTrips`（13 个用例全绿），断言导出 XML 无裸控制字符 + 二进制字节级还原。
- 已用修复代码重新生成 `retest-data/redis-retest.xml`（裸控制字符 0，可正常解析，binary 值为 `0x'000102FF8000'`），并实测导入成功。
- 教训：用户手上已损坏的旧 XML（含裸 0x00）无法事后修复，只能重新导出。

- 现象：IDEA 直接运行 RDP 连接后本地拷贝内容远程右键能显示"粘贴"，打包产物 EasyShell.app 不行。RDP 实例 192.168.3.34:3389/oyzh。

  3. `FixedClipChannel.announceLocalFormats()` 加 debug 日志（跳过通告的原因 / 空格式列表），便于诊断。
