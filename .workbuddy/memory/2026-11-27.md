### XML 导出含裸控制字符导致导入 ParseError（用户复测发现，已修）
- 现象：用户导出 db0 为 XML 后导入报 `XMLStreamException: 在文档的元素内容中找到无效的 XML 字符 (Unicode: 0x0)`。
- 根因：`ShellRedisKeyUtil.keyValue()` 用 `Jedis.get(String)` 以 UTF-8 解码二进制值（0xFF→U+FFFD 不可逆）；且 `isRawEncoding()` 只认 object encoding=="raw"，短二进制是 `embstr`，漏判，值走 `new String(bytes)` 把 0x00/0x01/0x02 裸写进 XML。`XMLUtil.escape()` 只处理 &<>\r，不处理 XML 1.0 禁止字符。
- 修复（3 处）：
  1. `keyValue()` string 分支改用 `client.get(db, key.getBytes(UTF8))` 读原始字节；新增 `isTextSafe()`（严格 UTF-8解码 + 检测 XML 禁止字符/代理项/0xFFFE），安全则按文本、否则保留 byte[]。
  2. `serializeNode()` string 分支按实际值类型判断（不再依赖 objectEncoding），byte[] 一律输出 `0x'hex'`（导入端 deserializeNode 已支持）。
  3. 导出 handler `escaped()` 增加最后防线：XML 格式剔除 0x00-0x1F 等禁止字符后再 XMLUtil.escape，保证文件必可解析。
- 回归测试：`ShellRedisDataLiveTest.binaryValueXmlExportIsParseableAndRoundTrips`（13 个用例全绿），断言导出 XML 无裸控制字符 + 二进制字节级还原。
- 已用修复代码重新生成 `retest-data/redis-retest.xml`（裸控制字符 0，可正常解析，binary 值为 `0x'000102FF8000'`），并实测导入成功。
- 教训：用户手上已损坏的旧 XML（含裸 0x00）无法事后修复，只能重新导出。

## 新增连接引导页：修复「全部」分类下搜索框被压扁（第三版，高度稳定性）
用户给 `ClearableTextField` 加了 `prefHeight="30"`，但切到「全部」时被压缩，其他分类正常。
- **实测诊断**（固定 960×640 Scene + snapshot 量高度）：「全部」search=25 / toolbar=25 / scroll=434 / footer=25；其他分类 30/30/424/30。即工具栏、搜索框、底部栏三处各被压 5px，滚动区反多占 10px。
- **根因**：`FXScrollPane` 未限制 `prefHeight`，其 pref 高度被 30 张卡片的 content 撑大 → `connect-guide-main`(`FXVBox`) 的 `adjustAreaHeights` 算出 `extraHeight<0` 进入收缩；JavaFX VBox 收缩时 `adjustingNumber=managed.size()`，把收缩量**均摊到全部子节点**，各节点最低压到自身 computed `minHeight`（搜索框约 25）。其他分类内容少，`extraHeight>0` 走增长模式，只有 `vgrow=ALWAYS` 的 ScrollPane 增长，故正常。
- **修复（全部在 FXML 声明）**：`FXScrollPane` 加 `minHeight="0" prefHeight="0"`（内容不再撑大父 VBox，剩余空间全由 vgrow 分配）；`ClearableTextField` 加 `minHeight="30" maxHeight="30"` 锁死预设高度；底部 `FXHBox.connect-guide-footer` 加 `minHeight="30"` 保护。
- **验证**：修复后 8 次分类切换（ALL/TERMINAL/FILE/S3/REMOTE/DATABASE/OTHER/ALL）高度恒为 30/30/424/30；`ShellAddConnectGuidFxmlTest` 6 个用例全通过；带主题 CSS 的 snapshot 视觉确认搜索框、卡片 4 列、底部栏、侧栏均正常无挤压。
- 顺带修正一个**既有的过时断言**：当前控制器 `matches()` 只按协议 id 子串匹配、FXML 卡片已无 `accessibleText` 中文别名，但测试里仍留着「搜索『数据库』→ 10」的旧断言（单独跑也失败，与本次改动无关），改为 `s3` → 5。若以后要恢复中文别名搜索，需同步补回 FXML `accessibleText` 与 `matches()` 逻辑。

## 列头高度随配置动态变化（修复）

- **现象**：关闭「显示字段类型/注释」后列头行数减少，但表头高度不变。
- **根因**：`ShellRecordColumn` 之前用 `box.heightProperty()` 监听实际高度并调 `tableView.setHeaderHeight()`；而 `FXTableView.setHeaderHeight()` 会把 `NestedTableColumnHeader` 的 min/pref/max 绑定到 `.column-header-background`，表头被**固定值钉住** → 内容变少后高度不回缩（越撑越大，只增不减）。
- **结论**：JavaFX 表头本身就会按列头内容自然布局。实测同一 `FXTableView` 在主题 `-fx-size: 40px` 的下限之上自动伸缩：3 行 = 49px，2 行/1 行 = 40px（回落主题默认高度），再打开又回到 49px。
- **修复**：删除 `refreshHeader()` 里的高度同步与 `setHeaderHeight` 调用（保留 `FXTableView.setHeaderHeight` 原 API，仅不再使用）；`refreshHeader()` 现在只 `setGraphic(buildHeader())`。
- **验证**：临时 JUnit 真实 Stage 快照（已删除）走右键菜单 `CheckMenuItem.fire()` 真实路径：49→40→40，再反向 40→40→49；`SQLiteRecordColumnTest` 8/8、`ShellSettingRecordColumnTest` 3/3、`*FxmlTest` 24 项全通过（合计 35）。
- **坑**：不要为多行列头强设表头高度；若要限制最小高度，改主题 CSS 的 `.column-header { -fx-size }`，不要在代码里 `setPrefHeight/MaxHeight`。

## 列头：空注释不占行 + 高度真正随内容伸缩

- **需求**：① 没有注释时不要显示 `--`；② 关闭类型/注释后列头不应该还是很高。
- **改动**：
  - `ShellRecordHeaderUtil.typeText()` 类型为空返回 `null`；`commentText()` 无注释返回 `null`（主键仍返回 `PK`）；删除 `COMMENT_PLACEHOLDER` 常量。
  - `ShellRecordColumn.buildHeader()` 跳过空文本，不再生成占位行。
  - 表头高度改为显式计算：`max(表内各列内容 prefHeight 的最大值 + 4, 30)`，通过 `tableView.setHeaderHeight()` 应用；`syncHeaderHeight()` 用 `FXUtil.runPulse` + `runLater(200)` 两轮（列头需先挂场景完成 CSS 才能量到 0.9em 字号）；`tableViewProperty` 变化时也同步一次。
- **两个关键坑**：
  - **每个列各设一次高度会互相打架**：表头高度是整表共享的，2 行的列（无注释）会把表头压到 33，裁掉 3 行的列。必须取表内所有列内容高度的**最大值**再设置。
  - 主题 `.table-view > .column-header-background .column-header { -fx-size: 40px }` 是单行表头 40px 的来源（不是 pref/min/max 属性，DIAG 里三者都是 -1）；所以「只显示字段名」时不干预就会保持 40px，必须显式设高度才会紧凑。
  - 量不到内容高度（列头尚未布局）时直接 return，避免先把表头压到 30 再弹回。
- **实测**：3 行 53px / 2 行 37px / 1 行 30px，双向切换都立即变化；`c_name`（无注释）只显示 2 行，PK 列显示 PK。
- **测试**：`SQLiteRecordColumnTest` 断言改为 2 行（SQLite 无注释）并校验 `commentText/typeText` 的空值行为；8/8 通过，`*FxmlTest` 24 项通过。

## 列头单行时仍然偏高（第三轮修复，量化诊断）

- **现象**：不勾选「显示字段类型/注释」后，列头只剩字段名，但高度看起来仍有 30px，观感偏高。
- **诊断过程**（临时 JUnit + 真实 Stage + 默认主题快照，测完即删）：
  - 主题 `-fx-size: 40px` 是单行表头自然高度；我们在 `applyHeaderHeight()` 里 `setHeaderHeight()` 确实生效（截图实测表头带高度 ≈ 数据行高度 ≈ 29~30）。
  - 内容实际只需要 17px（单行）/33px（两行）/49px（三行），也就是说**单行时的高度完全由 `MIN_HEADER_HEIGHT = 30` 托底**，`+HEADER_PADDING(4)` 根本没起作用。
  - 用户截图量化：表头带 58 设备像素、数据行同 58 设备像素（2x 缩放下即 ~29px），确认不是「没生效」而是「下限太大」。
- **修复**：`MIN_HEADER_HEIGHT` 30 → 22，`HEADER_PADDING` 改为单边 2（合计 +4）。
  - 实测：3 行 53px（不变）、2 行 37px（不变）、**1 行 30 → 22px**；三档双向切换即时生效，快照确认文字不裁切、不贴边。
  - 顺手补：`refreshHeader()` 里给新 graphic 加 `sceneProperty` 监听，未激活标签页首次显示时再同步一次高度，避免测不到内容高度而保留切换前的高度。
- **经验**：列头高度 = max(内容 prefHeight + 4, 22)；**不要再靠下限兜底**，下限只要大就会把单行表头顶得很胖。`box.prefHeight()` 需在 `applyCss()` 后量，且必须整表取最大值。

## MongoDB 字段信息弹窗的标签行（主键 / 嵌套字段）

- **需求**：Mongo 字段信息弹窗也要有标签，比如 `_id` 显示“主键”。
- **实现**：
  - `ShellMongoNodeUtil.generateTags(MongoColumn)`：`is_id()` → 主键（`I18nHelper.primaryKey()` + `tag_primaryKey`）；字段名含 `.` → 嵌套字段（新增 i18n `shell.mongo.nestedField`，8 语言，样式 `tag_unsigned`）。两者互斥（`a._id` 不会被判为主键）。
  - FXML 在“类型”行后插入 `tagsBox` 行（`managed=false visible=false`），内含 `SystemLabel %base.tags` + 内层 `tagsContainer`（FXHBox）。
  - 控制器 `fillTags()`：清空 `tagsContainer` → `addChild` → `display()` → 设置 margin；无标签时 `tagsBox.setVisible(false)`。
  - 高度：`onPopupInitialize` 记录 `baseHeight = max(root.getRealHeight(), root.getPrefHeight())`（=125），有标签时 `root.setRealHeight(baseHeight + 30)`，实测弹窗 125 → 155，无标签时不留空行。
- **踩坑 1**：`tagsBox.getChildren().clear()` 会把 FXML 里的 `SystemLabel("标签")` 一起清掉，导致标题消失 —— 标签必须加到内层容器，只清内层。
- **踩坑 2**：`PopupWindow` 显示后 `setHeight()` 不生效（popupH 恒为 125，内容却被撑到 155 → 裁切）。唯一可靠的是在 `onWindowShowing` 之前把内容 `prefHeight` 改好，让 popup 显示时按内容定尺寸。
- **踩坑 3**：`PopupManager.parsePopup` 内部是 **static 单例 PopupExt**，同一 JVM 只能正常初始化一次；`hide()` 后 `content()` 返回 null。多场景预览要么分开跑 JVM，要么在同一个 popup 上反复 `fillColumn`。
- **顺带修复**：`css/db/db.css` 的 `.tag_*` 只有背景色且都是浅色，暗色主题下浅色文字压在浅底上几乎看不清。统一加 `-fx-text-fill: #1f2328` + `-fx-padding: 1 6 1 6` + `-fx-background-radius: 4`（只有各库字段信息弹窗的 `generateTags` 用到这些类，影响面可控），亮/暗主题都快照确认清晰。
- **测试**：`ShellMongoFieldInfoPopupTest` 扩到 4 个用例（新增 `testGenerateTags`、弹窗内断言 tagsBox 可见性与高度 +30），全部通过；`SQLiteRecordColumnTest` 8/8、`ShellSettingRecordColumnTest` 3/3、`MongoCollectionDesignFxmlTest` 4/4 通过；`I18nResourceIntegrityTest` 仍是那 3 个既有失败。
