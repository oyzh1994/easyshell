## ZK 导入/导出/传输代码走查（只读，未改代码）
- 入口：controller/zk/data/{ShellZKDataImportController,ShellZKDataExportController,ShellZKDataTransportController}；处理器：data/zk/handler/{Import,Export,Transport}Handler；文档：docs/comment-review/data-redis-zk.md（仅描述性）。
- 主要发现：
  1. 导入字符集方向写反：`TextUtil.changeCharset(data, UTF-8, config.charset())`，读取器已按 config.charset() 解码，应为 config.charset() → UTF-8；且 `ShellZKClient.create/setData(String)` 用平台默认 `getBytes()`，非 UTF-8 文件往返会乱码。
  2. 导出固定 `new String(bytes, UTF-8)`，非 UTF-8/二进制数据不可逆；Excel 读取器返回 Double/Date，导入处 `(String) record.get` 会 ClassCastException。
  3. 导出中断失效：`success` 包装 RuntimeException，error 回调解包后直接 return，`loopNode` 继续递归整棵树。
  4. 导入未校验文件是否已选（`showStep3` 只检查连接），未选文件时 `doImport` 会 NPE；已存在节点只更新数据、不更新 ACL。
  5. 传输从 `/` 全量递归、无路径/过滤配置；临时节点连同其子节点一起跳过；不复制 ACL/配额；节点不存在时 `processedDecr()` 会把计数变负。
  6. 三个控制器异常判断 `e.getClass().isAssignableFrom(InterruptedException.class)` 方向不严谨，应改 `e instanceof InterruptedException`。
- 用户仅要求“看下”，本轮未修改代码；若后续要求修复，优先处理 1/2/3。

## ZK 导入/导出/传输修复与测试（同日，已改代码）
- 修复文件 8 个：3 个 handler、3 个 controller、导入/传输 FXML。
- 关键决策： charset 统一表示「文件编码 = zk 数据编码」。导出用 `new String(bytes, TextUtil.getCharset(config.charset()))`，导入用 `str.getBytes(charset)` 走 byte[] 重载，保证字节级往返（修复 UTF-8/GBK 乱码及平台默认 getBytes 问题）。
- 导出中断：error 回调识别 InterruptedException 链并 rethrow RuntimeException，让 loopNode 递归真正停止；控制器判断改为 `e instanceof InterruptedException || e.getCause() instanceof InterruptedException`。
- 导入：`recordValue()` 统一处理 Excel Double/Date（BigDecimal 去尾零）；已存在节点在 includeACL 时同步 setACL；showStep3 校验文件选择。
- 传输：新增 nodePath 字段 + UI 输入（默认 `/`），缺失节点改 processedSkip 避免计数变负。
- 测试：`src/test/java/cn/oyzh/easyshell/data/zk/handler/ShellZKDataHandlerTest.java`，内存 ShellZKClient mock，11 个测试覆盖 json/csv/xml/excel 往返、GBK 字符集、Excel 数字单元格、ACL 更新、导出中断、传输跳过/更新策略/负计数。`mvn -Dtest=ShellZKDataHandlerTest test` 全绿。
- 已知框架限制：base-store 的 TxtTypeFileWriter 不写引号而 TxtTypeFileReader 只解析引号内内容，txt 格式往返不可用；ZK UI 未暴露 txt 选项，故不修复。临时节点在 ZooKeeper 中不能有子节点，“跳过临时节点及其子节点”不是缺陷。

## 真实 ZK 实例端到端测试（127.0.0.1:2181）
- 新增 `src/test/java/cn/oyzh/easyshell/data/zk/handler/ShellZKDataLiveTest.java`（12 个测试，默认连接 127.0.0.1:2181，可用 -Dzk.host 覆盖，连不上自动 Assume 跳过）。所有数据写在随机根 `/easyshell-data-it-<uuid>` 下并在 @After 递归清理；传输目标端用同一实例不同 chroot 的真实 ZooKeeper 连接，实现路径隔离。
- 覆盖：json/csv/xml/excel 四种格式 + 中文/emoji/`<&>'`/逗号/换行/Tab/首尾空格/空数据/长文本/深层路径/Unicode 路径；GBK 往返；digest ACL 往返；手写文件异常行；导出中断；传输创建/跳过/更新/字符集转换；二进制字节保留。
- 真实实例暴露的额外 bug（已修）：
  1. 传输源节点不存在时 `getData` 抛 `KeeperException.NoNodeException`，原代码落到外层 catch 执行 `processedDecr()`，计数变 -1；改为先 checkExists，并对 NoNodeException 单独按 skip 处理。
  2. base-store 的 `XmlTypeFileWriter` 直接拼接字段值不转义，`&` 导致导出 XML 无法解析；在导出 handler 增加 `escaped()`（xml 格式转义 & < > 和 \r），StAX 读取器自动还原。
  3. `TextUtil.changeCharset(byte[], Charset, Charset)` 用 `==` 判断字符集相同；在传输 handler 增加 `convert()`，按名称比较后直接返回原字节，避免同字符集传输时二进制数据被有损解码/编码。
- 测试同步加固：`MemoryZKClient.getData` 缺失节点改抛 NoNodeException 以匹配真实 ZK；mock 测试补 XML 特殊字符往返。
- 结果：`mvn -Dtest=ShellZKDataHandlerTest,ShellZKDataLiveTest test` → 12 + 12 全绿，0 失败。
- 注意：文件导出为文本格式，任意二进制字节（如 0xFF）在「导出→导入」中无法无损（解码替换字符）；仅传输在同字符集下可字节级保留。XML 1.0 还不支持 U+0001 等控制字符。
- 测试隔离教训：传输目标 chroot 必须建在随机根 **内部**（如 `<root>/transport-dst`），建成兄弟节点会导致 @After 递归清理漏删。已修正并确认重跑无新增残留。
- 早期失败运行遗留一个 `/easyshell-data-it-f11a727a-...` 节点树，其中 `chinese` 节点带受限 ACL（getACL/getChildren 均 NoAuth），常规客户端无法删除；如需彻底清理需 ZK 管理员权限。
